## 12. Mobile sign-in fix — body-borne refresh token + tempToken 2FA (Replit Expo app)

**Root cause ("Sign-in could not be completed" — mobile):**
1. **Refresh token sirf HttpOnly cookie me milta tha** (`Domain=localhost`) —
   login/signup/refresh JSON body me kabhi `refreshToken` nahi tha. React Native
   cookie persist/use nahi kar sakta → mobile ke paas refresh token hi nahi tha.
2. **`POST /v1/auth/refresh` sirf cookie padhta tha** — body `{refreshToken}` pe
   `401 Missing refresh token`. Replit ko contract "Body: { refreshToken }" bataya
   gaya tha; backend accept hi nahi karta.
3. **2FA contract mismatch:** login `{ requires2fa: true }` bhejta tha bina `tempToken`;
   `POST /v1/auth/2fa/verify` enrollment-confirm endpoint tha (Bearer + `{code}` only),
   jabke contract tha "Body: { code, tempToken }".

**Fix (backward-compatible — web cookie flow bilkul intact):**
- `packages/shared/src/schemas.ts`: `refreshTokenBodySchema` (refresh/logout body),
  `twoFactorLoginSchema` (code + tempToken). Strict schemas as-is.
- `apps/api/src/jwt.ts`: `signTempToken`/`verifyTempToken` — 10-min JWT, audience
  `${jwt.audience}-2fa` (access-token verification isi audience check se reject karta —
  audience-mismatch test HTTP suite me).
- `auth-service.ts`: login → `{ requires2fa: true, tempToken }`; naya
  `completeTwoFactorLogin()` — tempToken verify → TOTP/recovery code → full session
  (lockout/counters same rules, garbage token DB-touch se pehle 401).
- `auth.controller.ts`: login/signup/refresh responses ab `refreshToken` JSON body me
  bhi (cookie set waise hi); refresh/logout body token accept (cookie fallback);
  `2fa/verify` dual-mode @Public — `{code,tempToken}` = anonymous login-completion,
  `{code}` + Bearer = enrollment confirm (purana behavior same).
